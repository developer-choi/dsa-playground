# Stack / Queue

넣은 것을 어느 쪽부터 꺼내느냐로 갈린다. **스택**은 넣은 역순(LIFO), **큐**는 넣은 순서대로(FIFO).

## 구현 (Array 기반 Stack)

배열의 끝(마지막 인덱스)을 "맨 위"로 쓴다. 앞쪽을 맨 위로 잡으면 push/pop마다 나머지 요소를 밀어야 해서 O(n)이 된다.

```js
const stack = [];

stack.push(value);
stack.pop();
stack[stack.length - 1];
```

## 구현 (Array 기반 Queue)

큐는 뒤로 넣고 앞에서 꺼낸다. 그런데 배열의 앞을 꺼내는 `arr.shift()`는 나머지를 전부 한 칸씩 당기므로 O(n)이다. 꺼낼 때마다 그 비용이 붙으면 순회 전체가 O(n²)로 무너진다.

그래서 실제로 꺼내지 않고 **읽을 위치만 앞으로 옮긴다.**

```js
const queue = [];
let head = 0;

queue.push(value);        // 뒤로 넣기
const front = queue[head++];   // 앞에서 꺼내기 — 배열은 그대로 두고 위치만 전진
```

배열이 줄지 않으므로 메모리는 넣은 만큼 계속 쓴다. 한 번 순회하고 버리는 탐색에서는 문제가 안 된다.

`arr.shift()`가 왜 O(n)인지, 같은 함정이 어떤 연산에 또 있는지는 [array.md](./array.md)의 「JS 배열/객체 연산 3카테고리」에 있다.

## 사례

### [pg-42584 주식가격](../../src/problems/stack-queue/pg-42584.ts)

각 가격마다 "자기보다 낮은 첫 번째 미래 가격까지의 거리"를 구해야 한다.
낮은 가격을 만나는 순간 그 원소의 답이 확정된다 → 그 전까지는 "미확정" 상태로 대기시켜야 한다.
대기 중인 미확정 원소들을 담아둘 공간이 필요하다.
새 가격이 들어오면, 그보다 높은 과거 원소들의 답이 한꺼번에 확정되어 꺼내 버려진다.
꺼내는 순서는 "최근에 들어온 것부터" — 넣은 역순으로 꺼내야 즉시 멈춤 조건이 성립한다.
LIFO → 스택이 필요하다.

### [pg-12909 올바른 괄호](../../src/problems/stack-queue/pg-12909.ts)

괄호 문자열이 올바른지 판정해야 한다.
닫는 괄호가 들어오면 "가장 최근에 열린" 괄호와 짝을 맞춰야 한다.
즉, 열린 괄호들을 쌓아두었다가 닫는 괄호가 올 때 가장 최근 것부터 꺼내 매칭해야 한다.
넣은 역순으로 꺼내는 = LIFO → 스택이 필요하다.
(단일 괄호 종류라면 카운터 하나로도 충분하지만, 여러 종류로 확장되면 종류 정보를 함께 쌓아야 해서 스택이 필연이 된다.)
