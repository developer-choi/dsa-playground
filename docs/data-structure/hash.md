# Hash

## 언제 쓰나 (형태 패턴)
- "**그룹별 집계**" — 키로 묶고 값에 누적
- "**짝짓기 / 존재 여부 확인**" — 키 lookup으로 O(1)
- "**중복 제거**" — 키의 유일성 활용

## 사례

### [pg-42579 베스트앨범](../../src/problems/hash/pg-42579.ts)

장르별로 재생수를 모으고, 장르 **간**에도 장르 **안**에서도 정렬해야 한다. 그룹별 집계 + 그룹 간·내 정렬이라는 형태다.

집계를 하려면 곡을 하나씩 보면서 "이 장르가 이미 저장됐나?"를 매번 물어야 한다. 곡이 N개면 이 질문도 N번이다. 배열에서 찾으면 한 번 묻는 데 O(N)이라 전체가 O(N²)가 되고, N=10,000이면 100배 차이가 난다. 그러니 **묻는 값 자체가 O(1)이어야** 한다 — 키로 바로 꺼내는 자료구조, 해시맵이다.

여기서 키가 **임의 문자열이고 종류가 많다**는 점이 해시맵을 실질적으로 필연으로 만든다. 키가 **단일·유한**이면 카운터나 배열로도 대체된다 ([pg-12909 괄호 케이스](./stack-queue.md)). "키 종류가 가변·다수 + O(1) 접근 필요"가 해시맵을 부르는 신호다.

저장 구조는 `{장르: {총재생수, [{곡 재생수, 곡 인덱스}...]}}` 로 잡는다. 장르 간 정렬은 총합으로, 장르 내 정렬은 곡별 재생수로 분리해 관리하기 위해서다.
