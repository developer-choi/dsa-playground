# DFS / BFS — 둘 중 무엇을 쓸까

각론은 [dfs.md](./dfs.md), [bfs.md](./bfs.md).

## 왜 배우는가

정렬된 데이터에 이분 탐색을 쓰듯 아주 효율적인 방법이 있는 반면,
**모든 경우의 수를 전부 봐야만 답이 나오는** 문제도 있다.

대표적인 예가 알파고다. 대국에서 나올 수 있는 수를 계산하고 예측해 최적의 수를 고르려면
가능한 수를 전부 펼쳐봐야 한다.

DFS와 BFS는 그 "전부 보기"를 어떤 **순서**로 하느냐의 차이다.

- **DFS (깊이 우선)**: 한 갈래를 끝까지 파고든 뒤, 막히면 돌아와 다음 갈래로 간다.
- **BFS (너비 우선)**: 갈라진 갈래를 한 단계씩 고르게 넓혀 나간다.

```
    0
   / \
  1   2
 / \
3   4

DFS: 0 → 1 → 3 → (되돌아옴) → 4 → (되돌아옴) → 2
BFS: 0 → 1 → 2 → 3 → 4
```

## 공간

- DFS는 지금 파고든 **한 갈래**만 들고 있으면 된다 → **O(최대 깊이)**
- BFS는 **같은 단계의 노드를 전부** 큐에 담아둔다 → **O(최대 너비)**

보통은 깊이보다 너비가 훨씬 크게 벌어지므로(분기가 많을수록 한 단계의 노드 수가 폭증) DFS가 공간을 덜 쓴다.
다만 한 줄로 길게 이어진 그래프처럼 깊이가 노드 수만큼 깊어지면 DFS도 O(V)까지 간다 — 최악은 둘 다 O(V)다.

## 최단 경로

BFS는 **가까운 것부터** 보므로, 목표에 처음 닿은 순간이 곧 최단 경로다. 거기서 멈추면 된다.
(단, 간선 가중치가 모두 같을 때. 가중치가 제각각이면 다익스트라 등이 필요하다.)

DFS는 먼저 닿은 경로가 최단이라는 보장이 없다. 최단임을 확신하려면 모든 경로를 다 펼쳐 비교해야 한다.

## 시간

둘 다 모든 노드·간선을 한 번씩 훑으면 **O(V + E)** 로 같다.
차이가 나는 건 **중간에 멈출 때**다.

- 답이 깊은 곳에 하나 있다 → DFS가 운 좋게 먼저 찌를 수 있다
- 답이 얕은 곳에 있다 / 최단 거리를 원한다 → BFS가 먼저 만나고 바로 끝낸다

## 정리

| | DFS | BFS |
|---|---|---|
| 순서 | 한 갈래를 끝까지 | 단계별로 고르게 |
| 공간 | O(최대 깊이) | O(최대 너비) |
| 최단 경로 | 보장 안 됨 | 처음 닿은 게 최단 |
| 구현 | 스택 (또는 재귀) | 큐 |
