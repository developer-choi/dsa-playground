# DFS / BFS — 완전 탐색과 그 두 순서

각론은 [dfs.md](./dfs.md), [bfs.md](./bfs.md).
노드·간선·V·E 같은 말과 그래프 종류는 [graph.md](./graph.md).

## 왜 배우는가 — 전부 봐야만 답이 나오는 문제

정렬된 데이터에 이분 탐색을 쓰듯 아주 효율적인 방법이 있는 반면,
**모든 경우의 수를 전부 봐야만 답이 나오는** 문제도 있다.

대표적인 예가 알파고다. 대국에서 나올 수 있는 수를 계산하고 예측해 최적의 수를 고르려면
가능한 수를 전부 펼쳐봐야 한다.

DFS와 BFS는 그 "전부 보기"를 어떤 **순서**로 하느냐의 차이다.

- **DFS (깊이 우선)**: 한 갈래를 끝까지 파고든 뒤, 막히면 돌아와 다음 갈래로 간다.
- **BFS (너비 우선)**: 갈라진 갈래를 한 단계씩 고르게 넓혀 나간다.

**DFS는 스택으로 짠다.** 재귀로도 되지만 깊이가 만 단위로 가면 호출이 쌓이다 죽고,
그 한계는 우리가 못 늘린다. 이 필기의 DFS 코드는 전부 스택이다.

```
    0
   / \
  1   2
 / \
3   4

DFS: 0 → 1 → 3 → (되돌아옴) → 4 → (되돌아옴) → 2
BFS: 0 → 1 → 2 → 3 → 4
```

## 최단 경로

BFS는 **가까운 것부터** 보므로, 목표에 처음 닿은 순간이 곧 최단 경로다. 거기서 멈추면 된다.
(단, 간선 가중치가 모두 같을 때. 가중치가 제각각이면 다익스트라 등이 필요하다.)

DFS는 먼저 닿은 경로가 최단이라는 보장이 없다. 최단임을 확신하려면 모든 경로를 다 펼쳐 비교해야 한다.

## 시간

둘 다 모든 노드·간선을 한 번씩 훑으면 **O(V + E)** 로 같다.
차이가 나는 건 **중간에 멈출 때**다.

- 답이 깊은 곳에 하나 있다 → DFS가 운 좋게 먼저 찌를 수 있다
- 답이 얕은 곳에 있다 / 최단 거리를 원한다 → BFS가 먼저 만나고 바로 끝낸다

## 아무거나 써도 되는 경우

위 절들은 전부 "언제 갈리나"를 다뤘다. 그런데 **안 갈리는 문제가 있고, 그게 꽤 흔하다.**

가르는 질문은 하나다 — **방문 순서가 답에 관여하는가.**

관여하지 않는 조건은 두 가지다. 하나, 중간에 멈추지 않고 **모든 노드를 다 본다**
(먼저 닿는 게 이득이 아니다). 둘, 각 노드가 내놓는 값이 **거기까지 온 경로만으로 정해진다**
(다른 노드를 언제 봤는지에 안 걸린다). 둘 다 맞으면 어느 순서로 훑든 같은 답이 나온다.

[wf-4 디렉토리 경로](../src/problems/tree/wf-4.ts)가 그렇다. 모든 리프의 경로 길이를 다 봐야 하고,
트리라 각 노드로 가는 길이 하나뿐이라 그 노드의 누적 길이는 순서와 무관하게 정해져 있다.
꺼내는 자리 한 줄만 바꾸면 BFS가 되고, 답도 코드 길이도 그대로다.

```ts
// ✅ DFS — 뒤에서 꺼낸다
const node = stack.pop();

// ✅ BFS — 앞에서 꺼낸다 (shift 는 O(N) 이므로 head 인덱스로)
const node = queue[head++];
```

**둘 다 ✅ 다.** 여기서 어느 쪽이 맞는지 고민한 시간은 그대로 손해다.

반대로 최단 경로·최소 횟수처럼 **먼저 닿는 것이 곧 답**이면 BFS여야 하고,
경로를 되짚어 가며 후보를 넣었다 뺐다 해야 하면(백트래킹) DFS여야 한다.

그러니 문제를 보고 DFS·BFS부터 고민하기 전에 이 질문을 먼저 던진다.
안 갈리는 문제인데 어느 쪽인지 붙들고 있으면 시간만 버린다.

## 정리

| | DFS | BFS |
|---|---|---|
| 순서 | 한 갈래를 끝까지 | 단계별로 고르게 |
| 최단 경로 | 보장 안 됨 | 처음 닿은 게 최단 |
| 구현 | 스택 | 큐 |
