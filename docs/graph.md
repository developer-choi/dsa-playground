# Graph

노드와 간선으로 "무엇과 무엇이 연결되어 있는가"를 나타낸 자료구조.
이 문서는 **그래프 자체**만 다룬다. 순회하는 방법은 [dfs.md](./dfs.md), [bfs.md](./bfs.md),
둘 중 무엇을 쓸지는 [dfs-bfs.md](./dfs-bfs.md).

## 용어

- **그래프 (Graph)**: 노드와 그 노드들을 잇는 간선으로 이루어진 자료구조.
- **노드 (Node)**: 연결 관계를 가진 각각의 데이터. **정점(Vertex)** 이라고도 한다.
- **간선 (Edge)**: 노드 간의 관계를 나타낸 선.
- **인접 노드 (Adjacent Node)**: 간선으로 **직접** 연결된 노드. 한 다리 건너 닿는 노드는 인접 노드가 아니다.

복잡도를 적을 때 **V는 노드(Vertex)의 개수**, **E는 간선(Edge)의 개수**다.

## 예시로 확인하기

```
로제 - 사나
 |
제니 - 딩코
```

- 노드: 로제, 사나, 제니, 딩코 (V = 4)
- 간선: 로제-사나, 로제-제니, 제니-딩코 (E = 3)
- 인접 노드
  - 딩코 → 제니
  - 제니 → 로제, 딩코
  - 로제 → 사나, 제니
  - 사나 → 로제

딩코와 로제는 간선으로 직접 이어져 있지 않으므로 인접 노드가 아니다.
제니를 거쳐야 닿는 관계다.

## 종류

종류가 여럿으로 보이지만 새 종류가 계속 생기는 게 아니라, **축 두 개의 조합에 이름이 붙은 것**이다.
외울 것은 두 가지뿐 — **방향이 있나 / 고리가 있나.**

축을 하나씩 보고, 조합에 붙은 이름은 이 절 끝에서 표로 모은다.

### 축 1 — 방향이 있나

**무방향 그래프 (Undirected Graph)** 는 간선에 방향이 없다.
간선 하나가 양쪽 관계를 동시에 나타내므로, A가 B의 인접 노드면 B도 A의 인접 노드다.
예: 친구 관계 — 내가 상대의 친구면 상대도 내 친구다.

**유방향 그래프 (Directed Graph)** 는 간선에 방향이 있다.
간선 하나는 한쪽 관계만 나타내고, 그 방향으로만 이동할 수 있다.
A → B 간선이 있어도 B → A로는 갈 수 없다 (그 방향 간선이 따로 있어야 한다).
예: 팔로우 관계 — 내가 상대를 팔로우해도 상대는 나를 팔로우하지 않을 수 있다.

```
무방향            유방향
로제 - 제니       로제 → 제니

로제, 제니 서로   로제에서 제니로만
오갈 수 있음      갈 수 있음
```

**유방향 · 단방향 · 유향 · 방향 있음은 전부 같은 말이다.**
이 문서와 다른 필기는 **유방향**으로 통일해 쓴다.

### 축 2 — 고리가 있나

**사이클(Cycle)** 은 출발한 노드로 되돌아오는 **닫힌 고리**다. 우리말로 순환·고리라고도 한다.

```
1 - 2
 \  |
   3     1-2, 2-3, 3-1 세 간선이 고리를 이룬다
```

노드 하나를 부르는 이름이 아니다. "순환하는 노드" 같은 건 없고, **간선들이 모여 만든 고리 자체**의 이름이다.

- 사이클이 하나라도 있으면 → **순환 그래프** (cyclic graph)
- 하나도 없으면 → **비순환 그래프** (acyclic graph)
- 비순환인데 방향까지 있으면 → **DAG** (Directed Acyclic Graph, 방향 비순환 그래프)

주의할 점은 **DAG가 "여러 길이 한 노드로 합쳐진다"는 뜻은 아니라는 것**이다.
일렬로 쭉 내려가기만 하는 그래프도 DAG다. 고리가 없다는 것 외에는 아무것도 말해주지 않는다.

```
      (1)
     ↙   ↘      고리는 없다 — 화살표가 전부 아래로만 향한다 → DAG
   (2)   (3)
     ↘   ↙      그런데 1→2→4 와 1→3→4, 두 길로 4에 닿는다
      (4)       4에서 나가는 화살표가 없으니 1로 돌아올 수 없다
```

이 구분이 순회에서 갈린다. 고리가 없어도 위처럼 길이 합쳐지면 같은 노드를 몇 번이고 다시 보게 된다
([dfs.md](./dfs.md)의 「서로 다른 노드가 같은 노드를 가리킨다」).

또 하나 주의할 점은 **무방향 그래프에서 간선 하나를 왔다 갔다 하는 건 사이클이 아니라는 것**이다.
같은 간선을 두 번 쓰기 때문이다. 그래서 무방향 트리는 코드상 부모-자식을 왕복할 수 있어도 **사이클이 없는 그래프**다.

### 정리 — 조합에 붙은 이름

| | 고리 없음 | 고리 있음 |
|---|---|---|
| **방향 있음** (유방향) | DAG | 순환 유방향 그래프 |
| **방향 없음** (무방향) | 트리 | 순환 무방향 그래프 |

이름이 붙은 건 왼쪽 두 칸뿐이다. 오른쪽 두 칸은 그냥 풀어 부른다.

## 표현 방법

그래프를 코드로 옮기는 방법은 두 가지다: **인접 행렬**과 **인접 리스트**.

아래 예시는 위 「예시로 확인하기」의 그래프에 번호를 붙여 쓴다 — 제니 0, 딩코 1, 로제 2, 사나 3.
간선은 0-1(제니-딩코), 0-2(제니-로제), 2-3(로제-사나). V = 4, E = 3.

### 인접 행렬 (Adjacency Matrix)

2차원 배열로 표현한다. `graph[a][b]` 는 "a와 b가 연결되었는가".

```
   0  1  2  3
0  X  O  O  X
1  O  X  X  X
2  O  X  X  O
3  X  X  O  X
```

```js
const graph = [
  [false, true,  true,  false],
  [true,  false, false, false],
  [true,  false, false, true ],
  [false, false, true,  false],
];

graph[0][2]; // true — 연결 확인 O(1)
```

무방향이면 대각선을 기준으로 대칭이다 (`graph[a][b] === graph[b][a]`).
그래서 간선을 넣을 때 `graph[a][b]` 와 `graph[b][a]` 를 둘 다 채워야 한다.

- 연결 확인: **O(1)**
- 공간: **O(V²)** — 연결 안 된 조합까지 전부 칸을 차지한다

### 인접 리스트 (Adjacency List)

각 노드마다 "그 노드에 연결된 노드들"만 나열한다.

```
0 -> 1 -> 2
1 -> 0
2 -> 0 -> 3
3 -> 2
```

```js
// 노드가 0..N-1 번호면 배열
const graph = [
  [1, 2],
  [0],
  [0, 3],
  [2],
];

// 노드 이름이 번호가 아니면 객체(Map)
const graph = {
  제니: ['딩코', '로제'],
  딩코: ['제니'],
  로제: ['제니', '사나'],
  사나: ['로제'],
};

graph[0].includes(2); // true — 0의 이웃을 훑어야 한다
```

- 연결 확인: **O(해당 노드의 이웃 수)** — 최악 O(V)
- 공간: **O(V + E)** — 실제 있는 간선만 저장한다

### 둘의 차이 = 시간 vs 공간

| | 연결 확인 | 공간 |
|---|---|---|
| 인접 행렬 | O(1) | O(V²) |
| 인접 리스트 | O(이웃 수), 최악 O(V) | O(V + E) |

행렬은 "0과 2가 연결됐나?"를 즉시 답하는 대신, 연결 안 된 조합까지 전부 저장한다.
리스트는 저장을 아끼는 대신, 연결 여부를 알려면 그 노드의 이웃을 훑어야 한다.

한편 **"한 노드의 이웃을 전부 순회"** 는 리스트가 O(이웃 수), 행렬이 O(V)로 리스트가 유리하다.
DFS/BFS는 이 순회를 반복하는 작업이라 보통 인접 리스트를 쓴다.

### 인접 리스트로 방향 나타내기

인접 리스트는 무방향·유방향을 **둘 다** 표현한다. 자료 구조가 다른 게 아니라, 양쪽에 다 적느냐 한쪽만 적느냐가 다르다.

`graph[a]` 는 "a에서 **갈 수 있는** 곳들"이다. 화살표 목록이라고 보면 된다.

```js
// 유방향 — 1에서 2로만 갈 수 있다
{
  1: [2],
  2: [],
}

// 무방향 — 1과 2가 서로 오갈 수 있다
{
  1: [2],
  2: [1],   // 양쪽에 다 적는다
}
```

무방향이라고 해서 별도 표기가 있는 게 아니라, **왕복 화살표 두 개로 적는 것**이 무방향이다.

주의할 점은 **코드만 보고는 무방향인지 유방향인지 알 수 없다**는 것이다.
위 두 예시는 문법적으로 같은 모양이고, 양쪽에 다 적혀 있으면 "무방향으로 쓴 것"이라고 읽을 뿐이다.

그래서 **인접 리스트를 만드는 그 순간에** 양쪽에 넣을지 한쪽만 넣을지를 의식적으로 정해야 한다.
이 선택이 순회 코드의 모양을 결정한다 ([dfs.md](./dfs.md)의 「원인은 인접 리스트를 만들 때 이미 정해진다」).

### "무방향"과 "양방향"은 뭐가 다른가

거의 같은 걸 가리키지만 말하는 층이 다르다.

- **무방향** — 관계 자체의 성질. "이 관계는 서로 오가는 관계다." 문제를 읽고 판단하는 것.
- **양방향** — 코드로 옮긴 모양. 인접 리스트에 화살표를 두 개 적는 것.

무방향 관계를 인접 리스트로 옮기는 방법이 양방향 적기 하나뿐이라 실무에선 같은 말처럼 쓴다.
다만 **유방향인데 마침 양쪽 화살표가 다 있는 경우**(서로 맞팔한 두 사람)도 코드 모양은 똑같다.
그래서 코드만 보고는 구분되지 않는다.
